# 世界尺度：一格等于多少米

游戏说方块，仿真和监控系统说米。这个比例就是 **`metres_per_block`**（每格多少米），
默认 **1.0**（即一格一米，所有旧配置行为完全不变）。

## 为什么需要它

游戏里的无人机不到一格大。1 格 = 1 米时，这就成了一架**一米宽**的四旋翼（还占掉场地 7% 的宽度），
所有位移读数都失真。**把世界按比例放大是解决办法**——不是把飞机缩小，也不是把数值硬编小：

| | 方块 | 米（上报给监控系统） |
| --- | --- | --- |
| 49×49 场地 | 49 格 | **12.25 m**（像一个真房间） |
| 无人机碰撞盒 | 0.9 格 | **0.225 m**（像一个真纳米四旋翼，占房间 1.8%） |
| 水平限速 | 5.6 格/秒 | **1.4 m/s**（后端契约，一个字都没改） |

## 怎么设置

```text
-Dmini_drone.world.metres_per_block=0.25 -Dmini_drone.arena.radius_x=24 -Dmini_drone.arena.radius_z=24
```

⚠️ **必须放在 JVM 参数位**（在 `-cp` 之前）。放在启动参数末尾（main class 之后）会被当成游戏参数丢掉——
这条是实测过的。PCL 里就把这三行加进 JVM 参数。

非法值（0、负数、乱填）会自动回退 1.0，不会污染整张地图的坐标（`WorldScaleTest` 守着这条）。

**场地要自己建大**：13 格在 0.25 尺度下只有 **3.25 m**（太小），所以要 49×49：

```text
/minidrone field clear      # 丢掉标记推导的旧场地
/minidrone arena clear
/minidrone arena create     # 读启动参数里的半径 24 → 49×49
```

## 它改了什么、没改什么

**改**：世界坐标 ↔ NED 的换算（`NedWorldTransform` 除以尺度、`DronePlacement` 乘以尺度）、
场地尺寸广播 `field_size_m`、场地中心偏移。换算**只在这两个边界上**。

**没改**：仿真内部、机体模型、速度/加速度上限、爬升下降率、坠机阈值、擦碰响应、信标字段——
全部仍是 SI（米）。物理与碰撞仍在**方块空间**解算，因为方块就在那里。
所以同一套「1.4 m/s 顶速 / 0.8 m/s 坠机阈值 / 0.5 m/s 擦碰能活」的判据在两种尺度下**都成立**。

**实测（`metres_per_block=0.25`，现有 13 格场地）**：

```text
Advertising training field 3.25x3.25 m (13,13 blocks, 0.25 m/block) ...
node scripts/course-check.mjs → 悬停 0.000 m、阶跃 1.09 s、顶速 1.39 m/s
```

与 1:1 时的数字**完全一致** ✔ ——这就是目的：监控系统看到的永远是米，游戏里的运动量随尺度放大。

## 一个必须知道的连带效果

尺度变小以后，**同样的"米"对应更多方块**：指令"悬停 1 米"在 0.25 尺度下是**离地 4 格**。
所以旧世界里按"1 格 = 1 米"直觉搭的障碍会**相对变矮**——实测里无人机直接**飞过**了那堵 2 格高的墙（它在 0.25 尺度下只有 0.5 m 高）。

搭障碍时按这个换算来：**障碍高度（米）= 格数 × 尺度**。想拦住贴地 1 m 飞行的飞机，
在 0.25 尺度下墙至少要 **4 格**高。
