# 从"游戏手感"到 ArduPilot SITL 级动力学：还缺什么

这份文档回答一个问题：**要让虚拟无人机像 SITL 里那样"动"，还要开发哪些模块**。
先给结论、再给清单，最后给两条路线（自己实现 vs 直接跑 ArduPilot SITL）的取舍。

## 0. 现在有什么（本模组的真实水平）

| 已有 | 说明 |
| --- | --- |
| 运动学积分 | 设定点（位置/速度/加速度前馈）→ 限速 1.4 m/s、限加速 2.0 m/s²、爬升 0.8 / 下降 0.6 m/s，20 Hz 固定步长 0.05 s |
| 姿态 | **运动学**的：由速度反推倾斜（限 12°），偏航按 `yaw_rate` 限幅（1.5 rad/s）——不是动力学解出来的 |
| 世界碰撞 | 每 tick 用方块碰撞形状求解（`PhysicsStep` + `Level#getBlockCollisions`），被挡住的轴速度归零、可沿墙滑行 |
| 自由落体 | 上锁即无推力，按重力加速（终速 8 m/s）下坠，落在方块上 |
| 撞击与自锁 | `ImpactModel` 按阈值判"接触/坠机"；坠机=上锁+自由落体+`safety_latched` 上报，`/minidrone drone reset` 清除 |
| 遥测 | 20 Hz 健康信标（含 `safety_latched`）、MAVLink 心跳/`ATTITUDE`/`LOCAL_POSITION_NED`/`EXTENDED_SYS_STATE` |

**没有**：力/力矩、电机、螺旋桨、气动、传感器噪声、EKF、能量、接触响应。

## 1. 差距清单（按模块）

### 1.1 六自由度刚体动力学（最大的缺口）
- 现状：位置是"想出来的"，姿态是"由速度扮出来的"，没有角动量。
- 需要：**力与力矩 → 线/角加速度 → 四元数积分**；机体惯量张量（对角近似即可）；
  角速率环（P/Q/R）先有阻尼（`τ = k·ω`）再加控制。
- 为什么值得先做：现在"侧倾"只在速度变化时出现，松杆即回到水平；真实多旋翼松杆后角速率还会继续（惯性），
  撞击也会翻滚。这一条做完，"像飞机"的感觉立刻上一个台阶。

### 1.2 电机 / 螺旋桨 / 电源
- 每电机推力曲线（RPM→thrust）、一阶响应（时间常数 ~50–100 ms）、混控矩阵（四旋翼 X 型）、
  推力饱和、电池电压跌落与内阻导致的推力下降。
- 带来：爬升率随电量变化、悬停需要"配平"、猛烈机动会饱和、低电时"顶不动"。

### 1.3 气动与风
- 最低成本高收益版：**机体轴二次阻力**（`F = -k·v·|v|`）+ 简单风场/阵风。
- 进阶：旋翼阻力与桨叶拍动、地效（近地升力增大）、姿态相关阻力（俯冲加速）。
- 现在限速 1.4 m/s 是硬编码的；有了阻力后"限速"应改为**推力极限下的自然结果**。

### 1.4 控制器（ArduPilot 的核心）
- SITL 里跑的是**真实固件**：速率环 → 角度环 → 速度/位置环，增益来自参数表，还有前馈与滤波。
- 要"等价"，只有两条路：移植控制律（工作量大且永远落后于固件），或**直接跑 ArduPilot**（见 §3）。
- 如果自研，最小可用版：级联 PID（角度→速率）+ 姿态限幅 + 位置环；用阶跃响应（超调/上升时间）验收。

### 1.5 传感器与状态估计
- IMU（噪声、偏置、温漂）、气压计、磁罗盘、GPS、外部导航（动捕）——各带采样率与延迟。
- 融合：EKF3（或把 EKF 交给固件）。**没有 EKF 就没有"外部导航融合"的真实行为**，
  现在后端要的 `EK3_SRC1_*` 参数在虚拟源里是"演"出来的（本模组直接应答参数表）。

### 1.6 接触、损伤与能量
- 接触响应：弹跳系数、摩擦、翻滚角速度（现在撞击=直接停下再判定坠机）。
- 损伤：桨叶损伤→推力损失（部分电机失效）→ 自旋/侧翻。
- 能量：电池电量与飞行时间挂钩（现在电量恒为 100%）。

### 1.7 时基与确定性
- 现在是"20 Hz 一步到位"的顺序耦合；SITL 是 400 Hz 主循环 + 传感器分频 + 独立物理步。
- 想要可复现实验（同一个输入得到同一条轨迹），需要：固定子步、录放（输入/状态序列）、随机种子化的噪声。

## 2. 优先级建议（按"每单位工作量换到的真实感"）

| 顺序 | 做什么 | 工作量 | 换到什么 |
| --- | --- | --- | --- |
| 1 | 姿态动力学最小闭环（角速率 + 阻尼 + 混控 + 惯量对角） | 中 | 姿态不再"跟速度走"；惯性、翻滚、松杆漂移 |
| 2 | 电机一阶滞后 + 推力上限 + 电池跌落 | 中 | 爬升/悬停/饱和/低电的手感 |
| 3 | 机体轴二次阻力 + 风 | 小 | 速度上限变成物理结果；有风/有阻力 |
| 4 | 接触响应（弹跳/翻滚）+ 桨损伤 + 失效 | 中 | 撞击不再只是"停住"（当前已有坠机与自锁） |
| 5 | 传感器噪声/延迟（先 IMU+气压） | 中 | 悬停漂移、控制抖动 |
| 6 | 时基改固定子步 + 录放 | 大 | 可复现实验、可对比 SITL |
| — | 自研完整 EKF、桨叶拍动、温湿度 | 很大 | 建议**不做**，除非要写论文 |

## 3. 路线选择：自研动力学 vs 跑 ArduPilot SITL

| | 自研（当前路线） | 跑 ArduPilot SITL 当飞控 |
| --- | --- | --- |
| 你得到什么 | 一个**游戏内的**被控对象，Minecraft 方块就是真实碰撞体，手感可调、可随时改 | 真实控制器、真实 EKF、真实传感器模型、真实参数表行为 |
| 你要写什么 | 上面 §1 的模块（量大，但每块都可单测） | **桥接层**：SITL 的 `SIM_` 物理后端（JSON/UDP）↔ Minecraft 世界；时钟同步；把动捕/位置喂回。控制律一行不用写 |
| 主要风险 | 永远"差不多但不像"；控制器自己写容易调不稳 | 双时钟与延迟导致抖动；方块世界的碰撞要自己塞进 SITL 的物理步（SITL 期望有地面高度场，不是体素） |
| 建议 | 先把 §2 的 1–4 做完（这才是"游戏内真实感"的来源） | 若目标是**验证飞控行为/参数**（而不是游戏手感），则走这条，代价集中在桥接 |

一句话：**想要"游戏里像真的"，做 §2 的 1–4；想要"和 SITL 一样的行为"，跑 SITL 并写桥接。**

## 4. 验收（每条都可测）

- 姿态：给 10° 阶跃侧倾指令，角速率峰值/上升时间/超调在设定范围内；松杆后角速率按阻尼衰减。
- 悬停：无风时 60 s 内位置漂移 < 0.2 m；加恒定风 1 m/s 后存在稳态偏差且随推力恢复。
- 爬升：指令 2 m，超调 < 0.05 m，到达时间与推力上限一致；低电（< 20%）时到达时间明显变长。
- 撞击：1.4 m/s 撞墙 → 上锁 + 自由落体 + `safety_latched=true`；0.3 m/s 贴墙 → 仅停止、不坠机。
- 时序：同一输入录制回放两次，轨迹逐点一致（确定性）。
